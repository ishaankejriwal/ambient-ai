Can Oracle Health's EHI export score the clinical decision support metrics?

The framework spreadsheet lists 15 methods and metrics for AI clinical decision support (CDS). This page writes each one as a formula in plain words, then shows which Oracle Health (Cerner Millennium) EHI export table and column supplies each piece of it. Pieces Oracle does not have are marked in red, with where to get them.

Of the 15 metrics, . Partly means Oracle has some of the inputs, such as the patient groups or the records a reviewer reads, and a reviewer, a survey or the vendor supplies the rest.

The same 15 cards exist for Epic and athenahealth. The formula and the variables are the same on all three pages, and only the tables and columns change.

Table, row and column

Table
One file in the export, like one tab of a spreadsheet. EKS_DLG_EVENT is the table of rule alerts.
Row
One line in that table. In EKS_DLG_EVENT one row is one time a Discern alert fired. In ENCOUNTER one row is one visit.
Column
One fact that every row has. EKS_DLG_EVENT.DLG_DT_TM is the time the rule fired.

Most formulas count rows, so each card says what one row stands for in every table it uses, and each chip in a formula repeats it.

The box around a variable shows where it stands. Visits is in the export. Note time is partly there: the export has a stand-in or part of the answer, and the rest comes from somewhere else. Survey score is not in the export.

The status beside each metric's name follows from those boxes. Yes means every variable is in the export. Partly means some are, or the export has a stand-in. No means none are. Some cards end the In Oracle part with "Also in the export". Those are columns that help but sit outside the formula, and they do not change the status.

Every rate and percent change comes out as a fraction. 0.05 is 5 percent, or 5 percentage points when it is the gap between two rates. Count each case once. If the bottom of a fraction is zero, report N/A.

How to read the Oracle model

  • Almost every column ending in _CD is a number that points at a pick-list. Look the number up in CODE_VALUE: CODE_VALUE.DISPLAY is the label your site shows, and CODE_VALUE.CDF_MEANING is a short fixed code that does not change between sites. Match on the fixed code where you can. Words below such as "sign" or "attending" are the usual meanings.
  • Every column ending in _ID is a real ID. PERSON_ID is the patient, ENCNTR_ID the visit, EVENT_ID the note, PRSNL_ID or PRSNL_PERSON_ID the staff member. Staff names and credentials are in PRSNL and CREDENTIAL.
  • Times (_DT_TM) are stored in UTC when the database runs in UTC mode, which most do. Confirm with your analyst. Some tables carry a matching _TZ column; where they do not, convert with the facility's time zone before taking a date.
  • Rows are versioned. Any update to a note adds a CLINICAL_EVENT row with the same EVENT_ID. The current version has an "open" VALID_UNTIL_DT_TM, which means the far-future date 31 Dec 2100. The same rule applies to CE_EVENT_PRSNL and CE_BLOB. Every formula below means the open row.
  • A note is a parent event with one child document event under it (CLINICAL_EVENT.PARENT_EVENT_ID). The text sits on the child, in CE_BLOB.BLOB_CONTENTS, in one or more chunks, compressed as CE_BLOB.COMPRESSION_CD says. Some documents are stored outside the database; CE_BLOB_RESULT.STORAGE_CD says where.
  • Who did what to a note is in CE_EVENT_PRSNL: one row per action (author, sign, cosign, modify, correct, review) with the person, a timestamp and a status (requested or completed).
  • The export is requested per patient. EHI_QUEUE_PERSON_RELTN holds the patient list for a request, and EHI_QUEUE.EHI_GROUP_ID groups the batches of a multi-patient request. Population metrics need a multi-patient request or many requests merged.
  • EHI_COL_EXCEPTION lists the columns Oracle leaves out of the export. Check any column on this page against it in your first file.

The tables that matter here

  • EKS_DLG_EVENT: one row each time a Discern alert fired, with its name in DLG_NAME, the user, the patient, the visit and any override reason. EKS_DLG lists the alerts with their titles.
  • ORDERS: every order. Its pharmacy orders are the medication lists a pharmacist reviews on the drug-related problem card.
  • PERSON, PERSON_CODE_VALUE_R and ENCOUNTER: the patient groups. ENCOUNTER.FINANCIAL_CLASS_CD stands in for insurance.
  • CE_EVENT_PRSNL, CLINICAL_EVENT and CE_BLOB: note actions with their times, and note text.

Where the AI shows up

  • If the tool shows its advice as a Discern alert, each alert is a row in EKS_DLG_EVENT. Ask your analyst for the alert's name, then filter on DLG_NAME. A passive alert shown in the chart is a row in PASSIVE_ALERT, with the rule that added it in ALERT_SOURCE and the message in ALERT_TXT.
  • If placing an order calls the tool as an outside service, ORDER_EXT_CALL_TRACKING has one row per call, with the service in SERVICE_NAME_TXT, the ORDER_ID and the call time. It holds no answer.
  • If it writes a summary into the chart, the summary is a CLINICAL_EVENT row. Pick it out as on the Oracle ambient AI page, by its own EVENT_CD or CONTRIBUTOR_SYSTEM_CD, and check a few known examples first.
  • For a tool that answers in its own window, the model has no table of its answers. Ask the vendor for its log, with the patient, visit, user and time of each request. Leave out ALERT_AUDIT_TRANSACTION and the tables under it. They log Oracle's own drug and allergy checks.

Words every card uses

The tool's alert
The Discern alert that shows the tool's advice, named in EKS_DLG_EVENT.DLG_NAME. Discern is Oracle's rules engine. A tool that shows no Discern alert has no rows here.
Test set
Past or made-up cases with a known right answer that the developer runs the tool on before go-live.
Open row
The current version of a versioned record, the one whose VALID_UNTIL_DT_TM is 31 Dec 2100. Every formula means the open row.
Before, After
Fixed periods before and after the tool went live, for the same clinicians.

Inputs outside the export

  • Scores from clinicians and pharmacists: guideline match, citation checks, made-up facts, drug-related problems, the five ratings, and checks of adherence calls.
  • Survey answers (TAM, Mini Z, mental effort).
  • The developer's test results: outputs on test cases, labels, XAI findings, answers to the made-up cases, and the focus group notes.
  • The vendor's log: answers shown outside a Discern alert, response times, click logs and draft text.
  • Time spent in the EHR. The model logs note actions only, so ask your analyst for Oracle usage reporting.
