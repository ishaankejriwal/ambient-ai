Can Oracle Health's EHI export score the ambient AI metrics?

The framework spreadsheet lists 20 metrics for ambient AI scribes. Oracle Health (the former Cerner Millennium) ships a data model with its electronic health information (EHI) export: 6,620 tables and their columns. This page writes each metric as a formula in plain words, then shows which of those tables and columns supplies each piece of it. Pieces Oracle does not have are marked in red, with where to get them.

Of the 20 metrics, . Partly means Oracle has some of the inputs, such as the patient groups or the notes to sample, and a survey, the vendor or a chart review supplies the rest.

The same 20 cards exist for Epic and athenahealth. The formula and the variables are the same on all three pages, and only the tables and columns change.

Table, row and column

Table
One file in the export, like one tab of a spreadsheet. ENCOUNTER is the visits table.
Row
One line in that table. In ENCOUNTER one row is one visit. In CLINICAL_EVENT one row is one version of one note or result.

One fact that every row has. ENCOUNTER.ARRIVE_DT_TM is the arrival time.

Most formulas count rows, so each card says what one row stands for in every table it uses, and each chip in a formula repeats it.

The box around a variable shows where it stands. Visits is in the export. Note time is partly there: the export has a stand-in or part of the answer, and the rest comes from somewhere else. Survey score is not in the export.

The status beside each metric's name follows from those boxes. Yes means every variable is in the export. Partly means some are, or the export has a stand-in. No means none are. Some cards end the In Oracle part with "Also in the export". Those are columns that help but sit outside the formula, and they do not change the status.

Every rate and percent change comes out as a fraction. 0.05 is 5 percent, or 5 percentage points when it is the gap between two rates. Count each case once. If the bottom of a fraction is zero, report N/A.

How to read the Oracle model

  • Almost every column ending in _CD is a number that points at a pick-list. Look the number up in CODE_VALUE: CODE_VALUE.DISPLAY is the label your site shows, and CODE_VALUE.CDF_MEANING is a short fixed code that does not change between sites. Match on the fixed code where you can. Words below such as "sign" or "attending" are the usual meanings.
  • Every column ending in _ID is a real ID. PERSON_ID is the patient, ENCNTR_ID the visit, EVENT_ID the note, PRSNL_ID or PRSNL_PERSON_ID the staff member. Staff names and credentials are in PRSNL and CREDENTIAL.
  • Times (_DT_TM) are stored in UTC when the database runs in UTC mode, which most do. Confirm with your analyst. Some tables carry a matching _TZ column; where they do not, convert with the facility's time zone before taking a date.
  • Rows are versioned. Any update to a note adds a CLINICAL_EVENT row with the same EVENT_ID. The current version has an "open" VALID_UNTIL_DT_TM, which means the far-future date 31 Dec 2100. The same rule applies to CE_EVENT_PRSNL and CE_BLOB. Every formula below means the open row.
  • A note is a parent event with one child document event under it (CLINICAL_EVENT.PARENT_EVENT_ID). The text sits on the child, in CE_BLOB.BLOB_CONTENTS, in one or more chunks, compressed as CE_BLOB.COMPRESSION_CD says. Some documents are stored outside the database; CE_BLOB_RESULT.STORAGE_CD says where.
  • Who did what to a note is in CE_EVENT_PRSNL: one row per action (author, sign, cosign, modify, correct, review) with the person, a timestamp and a status (requested or completed).
  • The export is requested per patient. EHI_QUEUE_PERSON_RELTN holds the patient list for a request, and EHI_QUEUE.EHI_GROUP_ID groups the batches of a multi-patient request. Population metrics need a multi-patient request or many requests merged.
  • EHI_COL_EXCEPTION lists the columns Oracle leaves out of the export. Check any column on this page against it in your first file.

Finding the scribe visits and notes

Oracle's model has no ambient table, so you have to build the list of scribe visits. Four ways, strongest first:

  • Ask the vendor for its session log with the visit each session belongs to. Join on ENCOUNTER.ENCNTR_ID if the vendor stores it, otherwise on the financial number (FIN, the billing account number) in ENCNTR_ALIAS.ALIAS plus the date.
  • Give AI-drafted notes their own note type when the scribe is set up. Then a scribe note is a CLINICAL_EVENT row whose EVENT_CD is that type, and a scribe visit is its ENCNTR_ID.
  • If the vendor writes notes through an interface or a service account, its notes may carry their own CLINICAL_EVENT.CONTRIBUTOR_SYSTEM_CD, CLINICAL_EVENT.ENTRY_MODE_CD or CE_DRAFT.ENTRY_MODE_CD, or show the service account in CE_EVENT_PRSNL.PROXY_PRSNL_ID. Check a few known scribe notes before relying on any of these.
  • Oracle's own ambient product (Clinical AI Agent) writes into the same note tables. No public column marks its notes, so ask your Oracle representative which of the above applies.

Words every card uses

Scribe visit
A visit on the list you built in the section above. Every status on this page assumes you have that list, and nothing here can be scored without it.
Scribe note
The current version of the clinician's progress note on a scribe visit: a CLINICAL_EVENT row with a document class, the progress note EVENT_CD, RECORD_STATUS_CD active and RESULT_STATUS_CD not in error or cancelled.
Clinician
The person who signed that note, CE_EVENT_PRSNL.ACTION_PRSNL_ID on the sign row. If the note is unsigned, use the attending in ENCNTR_PRSNL_RELTN.
Open row
The current version of a versioned record, the one whose VALID_UNTIL_DT_TM is 31 Dec 2100. Every formula means the open row.
Before weeks, After weeks
The weeks before and after that clinician's first scribe visit.
Comparison group
For any before-and-after metric, also compare against clinicians in the same specialty who did not get the scribe. Visit counts and timing also move with templates, vacations and panel changes.

Inputs outside the export

  • Audio or transcripts, so no word error rate.
  • Time spent in the EHR. The model logs note actions only. Oracle's usage reporting (Lights On Network) is a separate product.
  • A session ID shared with the vendor. The join is on the visit.
  • Survey answers (NASA-TLX, burnout, SUS).
  • An accent column. PERSON.LANGUAGE_DIALECT_CD is the closest thing and is rarely filled.

The model does have a work-RVU table (PFT_RVU_CONTENT), but only sites that run Oracle's patient accounting load it.
